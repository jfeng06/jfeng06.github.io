05 / AI INFRASTRUCTURE

Serverless Hybrid
AI Cluster

Twelve nodes. Two compute platforms. A local system for model inference, autonomous coding agents, and full-stack development workloads.

Team deployment

The goal

Build a local compute platform that can run AI agents, serve models, and execute development tasks without renting external inference compute. The cluster hosts Model Context Protocol (MCP) servers and background automation for mySpecSheet, keeping model execution and data manipulation on local infrastructure.

My contribution

I worked with the team to build and connect the 12-node cluster, configure its inference networks, and deploy a coding-agent harness across NVIDIA and Apple hardware. My work included the local routing control plane, specialized model deployments, MCP services, and containerized automation pipelines.

Two platforms, distinct roles

Eight NVIDIA DGX Sparks run CUDA inference through vLLM and Ray on Debian. Their 100GbE ConnectX-7 RoCE v2 fabric recorded a 12 µs average round-trip latency. Four Mac Studios handle agent orchestration, MCP servers, and Qdrant, while also running Kimi K2.7, a 1T-parameter mixture-of-experts model, sharded through Exo and JACCL. The Mac nodes provide 768 GB of pooled unified memory over a Thunderbolt fabric measured at 38.5 Gbps. CUDA and Metal workloads stay within their respective platforms.

A local serverless control plane

Here, “serverless” means callers submit work without managing the underlying services. A fine-tuned Nemotron 3 Ultra, a 550B mixture-of-experts model, classifies task envelopes and returns structured routing decisions. A scheduler dispatches those decisions to pre-warmed systemd services or Ray worker pools. Reported routing latency is 24 ms per route. The control plane also considers queue depth, model selection, and service health.

Specialized model serving

Gemma 4 31B-Instruct serves diagnostics and MCP tasks after QLoRA fine-tuning on 14,200 instruction pairs covering diagnostic schemas, engineering logs, and tool traces. Gemma 4 Diffusion uses a LoRA trained on 8,400 paired images, including ECU wiring diagrams, pinout schematics, and simulation wireframes. Its two-node pipeline separates denoising from image decoding. Kimi handles long-context code workloads on the Mac nodes, while the DGX Sparks handle GPU inference and verification workloads.

Agents and background automation

The coding harness uses NVIDIA NemoClaw and OpenShell with Docker sandboxes for code generation, testing, and test verification. Background scrapers and RSS readers ingest and vectorize news feeds, while LlamaIndex and Qdrant index repository files for retrieval. Local, containerized execution avoids external inference API charges for these workloads and reduces exposure of project data to external model services.
